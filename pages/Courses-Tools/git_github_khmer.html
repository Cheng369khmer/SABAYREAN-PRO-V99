ស្វែងយល់ពី Git & GitHub

Version Control System · Beginner to Advanced Guide

5 ជំពូក Core Concepts Workflow
១
តើអ្វីជាភាពខុសគ្នារវាង Git និង GitHub? ▼

មនុស្សជាច្រើនតែងតែច្រឡំថា Git និង GitHub គឺជាមួយ។ តាមពិតវាមានតួនាទីខុសគ្នាស្រឡះ៖

💻
Git (កម្មវិធីក្នុងម៉ាស៊ីន)
ជាឧបករណ៍ (Tool) សម្រាប់កត់ត្រា និងតាមដានរាល់ការផ្លាស់ប្តូរកូដ (Version Control) នៅក្នុងកុំព្យូទ័ររបស់អ្នកផ្ទាល់។ វាអាចដំណើរការបានដោយមិនបាច់មានអ៊ីនធឺណិត។
☁️
GitHub (វេទិកាលើពពក)
ជាសេវាកម្មវេបសាយ (Cloud Hosting) សម្រាប់ផ្ទុកកូដដែលអ្នកបានកត់ត្រាដោយ Git។ វាជួយឱ្យអ្នកអាចចែករំលែកកូដ និងធ្វើការងារជាក្រុមបាន។
💡 ឧទាហរណ៍ងាយយល់៖ Git គឺដូចជា "កាមេរ៉ាថតរូប" ដែលជួយថតចម្លងការងាររបស់អ្នកទុក។ ចំណែកឯ GitHub គឺប្រៀបដូចជា "Facebook ឬ Google Photos" ដែលអ្នកយកទិន្នន័យពីកាមេរ៉ាទៅបង្ហោះ (Upload) ដើម្បីរក្សាទុកលើអ៊ីនធឺណិត និងចែករំលែកឱ្យគេឃើញ។
២
ការរៀបចំដំបូង (Initial Setup) ▼

មុននឹងចាប់ផ្តើមប្រើ Git អ្នកត្រូវប្រាប់វាឱ្យស្គាល់អត្តសញ្ញាណរបស់អ្នកសិន ដើម្បីកុំឱ្យច្រឡំពេលធ្វើការជាក្រុម។ បើក Terminal (ឬ Git Bash) រួចវាយកូដខាងក្រោម៖

# កំណត់ឈ្មោះរបស់អ្នក
git config --global user.name "CHENG Cyber"

# កំណត់អ៊ីមែលរបស់អ្នក (ត្រូវប្រើអ៊ីមែលដែលបានចុះឈ្មោះក្នុង GitHub)
git config --global user.email "your.email@gmail.com"

# ពិនិត្យមើលព័ត៌មានដែលបានបញ្ចូល
git config --list
៣
វដ្តការងារមូលដ្ឋាន (Basic Workflow) ▼

រាល់ពេលដែលអ្នកសរសេរកូដ អ្នកត្រូវឆ្លងកាត់ដំណើរការទាំង ៤ ដំណាក់កាលនេះជានិច្ច៖

១
Init / Clone (ចាប់ផ្តើម)
កំណត់ Folder កូដរបស់អ្នកឱ្យក្លាយជាទីតាំងគ្រប់គ្រងរបស់ Git ដោយប្រើប្រាស់ git init ឬទាញកូដពី GitHub មកដោយប្រើ git clone។
២
Add (ត្រៀមខ្លួន)
នៅពេលអ្នកកែឯកសារ អ្នកត្រូវបញ្ជូនវាទៅកាន់ Staging Area (ទីតាំងរង់ចាំ) ដោយប្រើ git add . ។ វាប្រៀបដូចជាការរៀបចំអីវ៉ាន់ដាក់ចូលក្នុងវ៉ាលី។
៣
Commit (រក្សាទុកចុងក្រោយ)
រក្សាទុកការកែប្រែជាផ្លូវការនៅក្នុងម៉ាស៊ីន ដោយប្រាប់ពីមូលហេតុនៃការកែប្រែ (git commit -m "សាររបស់អ្នក")។ ដូចជាការចាក់សោវ៉ាលី។
៤
Push (បញ្ជូនឡើងពពក)
រុញកូដដែលបាន Commit ទាំងអស់ទៅកាន់ GitHub ដើម្បិរក្សាទុកសុវត្ថិភាព និងចែករំលែក (git push)។ ប្រៀបដូចជាការផ្ញើវ៉ាលីឡើងលើយន្តហោះ។
៤
Commands សំខាន់ៗប្រចាំថ្ងៃ ▼ 
# ពិនិត្យមើលស្ថានភាពកូដ (ថាមានឯកសារណាត្រូវកែប្រែខ្លះ)
git status

# ទាញយកកូដថ្មីៗពី GitHub មកកាន់ម៉ាស៊ីន (ពេលធ្វើការជាក្រុម)
git pull

# មើលប្រវត្តិការងារ (ប្រវត្តិ Commit) ទាំងអស់
git log

# បង្កើតមែកធាង (Branch) ថ្មីដើម្បីសរសេរមុខងារថ្មីដោយឡែក
git checkout -b feature-login
៥
ចំណុចគួរជៀសវាង (Bad Practices) ▼
❌
កុំ Commit ដោយសារមិនច្បាស់លាស់កុំសរសេរ git commit -m "update" ឬ "fix" ដដែលៗ។ ត្រូវបញ្ជាក់ឱ្យច្បាស់ ឧទាហរណ៍៖ "fix responsive issue on mobile menu"។
⚠️
កុំធ្វើការលើ Main Branch ផ្ទាល់រាល់ពេលមានកិច្ចការថ្មី ត្រូវបំបែក Branch (Branching) ជានិច្ច ជៀសវាងការខូចកូដដើមដែលកំពុងដំណើរការ។
⛔
កុំ Push ឯកសារសម្ងាត់ចូល GitHubត្រូវប្រើប្រាស់ឯកសារ .gitignore ដើម្បីលាក់ទិន្នន័យដូចជា Passwords, Database Credentials ឬ Folder ធំៗដូចជា node_modules ។
